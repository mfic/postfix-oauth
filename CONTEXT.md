# Domain glossary

- **Relay** — the dockerized Postfix MTA; accepts mail from printers, delivers to Microsoft 365.
- **Printer** — an SMTP client with no modern auth: connects from a trusted network or with a per-printer SASL account.
- **Trusted network** — an IP or CIDR in `config/trusted_networks`; clients there may relay without authentication. Not every such client is a printer.
- **Sender lockdown** — the whitelist in `config/allowed_senders`; binds every client, trusted or authenticated, except that a client sender mapping replaces the sender instead.
- **Client sender mapping** — optional entry in `config/client_senders` giving one printer (source IP or SASL account) its own mailbox. The relay overwrites that printer's envelope sender and From, then re-injects the message, so outbound modes need no knowledge of it. Unmapped printers stay under the sender lockdown only.
- **Failure notice** — a message Postfix itself generates (bounce or postmaster notice). It has no mailbox of its own, so in graph mode a bounce becomes a plain text notice, with the message content only if `FAILURE_NOTICE_ATTACH_MESSAGE=yes`, to `FAILURE_NOTICE_MAILBOX`, sent as `FAILURE_NOTICE_SENDER`, if those are set; otherwise, and for postmaster notices, `graph-send.sh` only logs it. `scripts/failure-notice.sh` builds the notice, and `graph-send.sh` decides whether one goes out and posts it. Interface, bounce on stdin: `details` (what failed, for the log), `plain <from> <to> [<status>]` (the notice; a status says Graph refused it with its attachment), `attached <from> <to>` (the notice with the failed message, or exit 1 if the bounce holds none).
- **Config tables** — `scripts/config-tables.sh`; the one reader of `config/`, with one line reader and one copy of the IP and mailbox rules. Interface: `access <dir>` (sender lockdown and client accounts into their tables, trusted networks checked, prints the `mynetworks` value), `client-senders <dir>` (client sender mappings into their tables and the sender policy, once `main.cf` is rendered), `is-mailbox <value>`.
- **Outbound mode** — how the relay hands mail to Microsoft 365: `graph` (Graph `sendMail` over HTTPS) or `smtp` (SMTP submission with XOAUTH2). Chosen per deployment by the compose file.
- **Outbound-mode adapter** — `scripts/outbound-<mode>.sh`; the one file that owns everything a mode needs. Interface (identical for every mode): `setup` (Postfix config + aux services at boot), `token-scope` (OAuth scope), `write-token <token> <ttl>` (that mode's token store, format and ownership included). Adding a mode = adding one adapter script; entrypoint and token scripts stay mode-agnostic.
- **Token store** — `/etc/tokens/token`; its format belongs to the adapter (raw bearer token for graph's pipe user, sasl-xoauth2 JSON for smtp).
